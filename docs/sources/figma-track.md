# Figma track: Idea To Demo

> **Source:** "Cal Hacks __ Figma.pdf" (the Google Doc linked from the live prizes page: https://docs.google.com/document/d/1HjzThDGveSLiilIdEPEHq12ZVLZ5eS0T8CQC5_m_-rg/edit)  
> **Captured:** 2026-10-24  
> **Summary:** Build anything from idea to working demo; judged on the *workflow* and a per-stage "stage log" of which Figma tools you used and why. Requires Figma Slides + public Figma files + edu verification.

## Context

Every team builds differently. Some start in a design tool, some start in code, and many bounce between the two. Figma now offers more than a canvas: Make can turn a prompt into a working prototype, and Figma agent can read and write designs and pass them to code. This challenge is about building a real project the way you normally would, then showing where each tool fits in your process.

## Mission

Take an idea to a working demo within the hackathon. Use any mix of tools. Figma's tools and agent capabilities are available; you decide at which stages they earn a place. Submit the demo plus a short **stage log** recording which tools you used at each step.

## Considerations

- Build what you were already going to build. Not judged on scope or technical difficulty; they care most about a clear problem, an honest account of how you built it, and a demo that works.
- Strong submissions show intentional tool choices: why each tool was used at each stage and what got passed from one stage to the next.
- Real process isn't a straight line. **Show the path you actually took and how you used Figma's tools to iterate.**

## Submission requirements

Figma files must be shared with **"Anyone" (can view)**. Three deliverables:

- Demo video (3 minutes max)
- Workflow artifact / **stage log** (200 words max per stage)
- **Figma Slides** demonstrating work & workflow (required), containing:
  - [Stage log] which Figma product you used & why (an example template is linked in the doc)
  - [Demo video] quick demo of the build
  - [Working code & prototype] embedded Figma files (Make and/or prototypes) + link to working code/repo
- **Be Edu verified.**

## Stage log

Four stages: **Ideation** (exploring and shaping the idea), **Prototyping** (something clickable), **Handoff** (moving a design/spec toward implementation), **Code generation** (producing working code).

For each stage: which Figma tool(s) (Design, Make, Figma agent, etc.) and why; about how many minutes; how well it worked (1–5); how the output made it into the final project.

Good workflow = **intentional**, **traceable** (idea → design → code visible), **honest about friction** (rework, dead ends, abandoned tools), **reusable** by another team.

## Judging criteria

- **Workflow design:** clear path idea → demo with each stage accounted for; tools chosen on purpose; log shows time, what worked, what broke; followable without the builder present.
- **Adoptability:** would a team use this workflow next time? Measurable before/after (time saved, steps cut, less rework)? Realistic given tool access?
- **Output quality:** demo works and does what's claimed; thoughtfully designed and usable; quality clear enough to judge the tools, not just the team.
- **Presentation / pitch:** problem, idea, and build process clearly told; logical narrative; persuasive about who it serves.
- **Innovation & creativity**
